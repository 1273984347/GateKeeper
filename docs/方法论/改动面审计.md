# 改动面审计

## 来源事故

M15 落地当天两起：①sed 负样本往返把 README 写出 CRLF 假修改；②`git checkout -- <file>` 把未提交的有效修复一并回退（doc-sync 立即报 1 FAIL 才发现）。源仓西游记仓铁律 10 同款纪律在案。

## 规则

1. 批量脚本/批量编辑执行完毕必 `git diff --name-only` 对比改动范围与预期清单；超出预期的非必要改动 `git restore` 回退。
2. 回退前先 `git diff <file>` 核实：工作区相对 index 还有哪些未提交的有效改动——index 已含全部有效改动时 checkout 才是安全还原路径。
3. sed/脚本改完检查行尾与文件末尾换行（.gitattributes eol=lf）。

## 验证方法

`git diff --name-only` 输出与手头任务的预期文件清单逐一对上；多余项逐个核实或 restore。
