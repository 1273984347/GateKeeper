# E1 铁律：声明 ≠ 落地，改后必 Grep 实证

## 来源事故

M8.5 自我深度审查（Self-DRL）：对 7 份核心文档跑六道门禁，7/7 判阻断——"文档声称已治理"与"引擎实测"全面背离（CHANGELOG v0.10.0）。此后历次 review 仍反复抓到"声明已做、实际未做/做过头"（如 M14 review 的越仓链接、M15 review 的对齐表过期状态行）。

## 规则

1. 任何文件修改后，对本次"声明"逐条 grep 验证落地：改了什么就查什么，禁止假收敛。
2. 新逻辑先跑负样本自测，再上全量；负样本要求"违例必红、恢复必绿"。
3. 文档里的每条主张（数字/路径/机制名）写前核实、写后 spot-check。

## 验证方法

`grep -n "<声明关键词>" <改动文件>` 命中且内容正确；门禁维度由 check-docs/doc-sync 机器兜底。

## 出处

CHANGELOG v0.10.0（M8.5）；交接文档「三」；GateKeeper CLAUDE.md 必守第 2 条。
